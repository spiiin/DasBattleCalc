# План: проверка атак (FFTA)

Цель: поле с юнитами, выбор атакующего и цели, тип атаки «Attack» (ближний бой и луки), направление юнитов
(поворот на 90°), расчёт результата — урон, шанс попадания, крит и всё, от чего они зависят, — с той же точностью,
что порядок ходов: формулы читаем в ROM и сверяем с игрой. Плюс снаряжение юнита и его влияние на характеристики.

Метод — тот же, что для порядка ходов (`notes.md`): найти поля в RAM → найти код игры, который их читает/пишет
(перехват записи в BizHawk + дизассемблер `thumb.py`) → модель на Python → сверка с живой игрой → перенос в daslang.

## Что уже видно в RAM тестового сейва (гипотезы, проверить)

| где | что | Marc |
|---|---|---|
| запись `+0x20…+0x27` | 4 × u16, вероятно W.Atk, W.Def, M.Pow, M.Res | 113, 112, 75, 90 |
| запись `+0x2A` | 5 × u16 id снаряжения (уже используется для скорости) | 129, 1, 288, 253 |
| запись `+0xF6…+0xFB` | две тройки байт (Move / Jump / Evade? база и текущее) | 07 04 01 07 04 03 |
| обёртка `+0x08 / +0x0A / +0x0C` | координаты на поле (пиксели? x, высота, y) | f0 a0 90 |
| обёртка `+0x1E / +0x1F` | сторона (уже используется), ещё один байт — возможно направление | 00 01 |
| таблица предметов `0x0851D180` | 32 Б: `+0x04` цена, `+0x08` тип, `+0x10…+0x17` знаковые бонусы, `+0x14` скорость (проверено) | |
| `0x080CA7A4(item, stat)` | геттер характеристики предмета: номер stat → поле записи (jump table) | |

## Этапы

### 1. Данные юнита и снаряжение
**Готово (2026-10-23)**: формулы и таблицы ROM — `notes.md` («Stats and equipment»), модель — `ffta_battle.das`
(`read_item`, `read_job`, `stat_total`), UI — секции Stats и Equipment в инспекторе, тест `tests/test_ffta_stats.das`
(экраны Status всех 5 юнитов тестового сейва совпадают). Не проверены предметы с бонусом Move / Jump.
- Подтвердить поля характеристик: сравнить с экраном статуса в игре (Lua-скриншот меню Status для каждого юнита)
  и с перехватом чтений при открытии статуса.
- Дочитать геттер `0x080CA7A4` (все 19 случаев) и функцию итоговой характеристики (как `0x080CA580` для скорости:
  база + Σ бонусов предметов + статусы) для W.Atk, W.Def, M.Pow, M.Res, Evade, Move, Jump.
- Имена предметов и тип оружия (меч, лук, кнутик…) — из ROM (текстовые таблицы; кодировка уже известна).
- UI: в инспекторе — секция «Equipment» со списком предметов и их бонусами; итоговые характеристики с разбивкой
  «база + снаряжение = итог».

### 2. Поле
**Готово (2026-10-23)**: карта `0x02007F10` (высоты, флаги; `notes.md`, «Battle map»), панель Battle → Field: сетка
с высотами, юниты цветом стороны со стрелкой направления; клик — выбор и атакующий, правый клик — цель, перетаскивание —
другая клетка, Q / E — поворот; калькулятор (сторона Auto, дальность оружия) считает по изменённым позициям.
Дальность Fight (кто кого может бить, 2026-10-23): правило игры `0x0809FEF0` — `notes.md`, «Fight reach», модель
`reach.py`, тест `tests/test_ffta_reach.das`; на поле досягаемые клетки атакующего подсвечены. Луки и ружья — только
расстояние, без высоты и линии огня; ближний бой — соседняя клетка с перепадом −3..+2; копья — особое правило.
Не сделано: ориентация как в изометрии игры.
- Найти карту боя: размер, высоты клеток (обёртки дают координаты; высоту клетки — по данным карты, Data Crystal
  описывает структуру карт `Final_Fantasy_Tactics_Advance/Maps`, 0x58 Б на карту).
- Подтвердить координаты и направление юнитов: Lua — подвинуть/повернуть юнита в игре, смотреть, какие байты меняются.
- UI: панель Battle — 2D-сетка (высота числом/оттенком клетки), юниты — кружки цвета стороны с именем и стрелкой
  направления. Выбор юнита кликом, перетаскивание на другую клетку, поворот на 90° (кнопки / клавиши Q/E).
  Изменения влияют только на расчёт (сейв не меняем).

### 3. Механика атаки (исследование)
**Готово для Fight без способностей (2026-10-23)**: формулы урона, шанса, крита — `notes.md` («Attack»), модель
`attack.py`, 18 замеров прогноза игры совпали. Найдено: скрытые +10 % к броску у не-врагов, крит = Evade работы / 10,
высота на Fight не влияет. Не проверены: стихии, урон крита и разброс на реальных ударах, support-способности, луки.
Найти в ROM процедуру обычной атаки (перехват записи в HP цели при атаке в игре → вверх по стеку вызовов) и вывести:
- **Урон**: от W.Atk атакующего, W.Def цели, оружия, расы/работы?, разброс (случайная часть — диапазон min..max),
  модификаторы направления (спина/бок), высоты, статусов (Protect, Berserk…), элементов оружия/брони, законов
  судьи (только чтобы показать «нарушение»).
- **Шанс попадания**: Evade цели, направление (спереди/сбоку/сзади), статусы (Blind и т.п.), щит/снаряжение.
- **Крит**: шанс и множитель (и откидывание при крите, если есть).
- **Луки и дальность**: дальность оружия, влияние высоты на дальность, траектория/препятствия (если игра их учитывает
  для обычной атаки), стреляет ли лук через юнитов.
- Отдельно: от чего зависит, видна ли «Attack» вообще (дальность, высота по Jump для ближнего боя).

### 4. Сверка с игрой
- Lua-сценарий: загрузить сейв, выбрать атакующего и цель через меню (Action → Fight/Attack), до подтверждения
  прочитать показанные игрой «урон / шанс» (игра показывает их в окне прицеливания) и сравнить с моделью;
  затем подтвердить и записать фактический результат (HP до/после, промах, крит).
- Перебор: несколько пар атакующий/цель, направления (поворачивать цель в игре или подменять байт направления в RAM),
  высоты; набрать статистику для шансов (много повторов с перезагрузкой сейва и разным RNG).
- Тест на daslang, как `test_ffta_turn_order.das`: модель против записанных из игры значений.

### 5. Калькулятор
**Первая версия готова (2026-10-23)**: вкладка Attack в Calc — атакующий, цель, сторона списками; модель
`ffta_attack.das` (перенос `attack.py`), тест `tests/test_ffta_attack.das` (17 замеров игры). Дальше: поле (этап 2),
способности, луки.
- Панель Calc: при выбранных атакующем и цели — «Attack» и результат: урон (min–max, среднее), шанс попадания,
  шанс крита и урон крита, из чего сложилось (разбивка формулы: W.Atk, W.Def, направление, высота, статусы, предметы),
  попадает ли цель в дальность.
- Выбор типа атаки: пока только Attack (ближняя / лук по оружию юнита); позже — способности.

## Риски и решения, которые стоит обсудить
- **RNG и «показанные» шансы**: если игра показывает шанс, сверяем с ним; фактические попадания — статистически.
- **Высоты и линия огня для луков** могут потребовать разбор данных карты — самая трудоёмкая часть, вынесена в этап 2.
- **Объём**: этапы 1 и 3 — исследование ROM, как с порядком ходов; UI (этапы 2, 5) после подтверждения полей.
- Порядок по умолчанию: 1 → 3 (без поля, цель и направление выбираются списком) → 4 → 2 → 5.

### 6. Способности (2026-10-23)
Support-способности юнита (Weapon Atk+, Magic Pow+, Turbo MP, Doublehand, Concentrate, Weapon Def+) и Battle Tech
Soldier в калькуляторе (список Action): формулы — `notes.md`, «Abilities», тест `tests/test_ffta_abilities.das`
(12 замеров игры). Дальше: способности других работ (эффекты из скриптов способностей), reaction-способности.
Способности всех работ (2026-10-23): эффекты по таблицам ROM (`notes.md`, «Ability effects») — урон и лечение по
формулам, ×2 / ×3, MP-урон, Drain, оживление, статусы (вредные / полезные), дальность и площадь; особые эффекты
(~30) помечены. Тест `tests/test_ffta_magic.das` (6 замеров игры).

### 7. Сверка на настоящих ударах (2026-10-23)
`live_probe.lua` (случайное зерно ГСЧ перед подтверждением) + `live_stats.py`: попадание, разброс урона и лечения,
урон крита и отбрасывание, +10 к броску у способностей — сходятся; стихии — по прогнозу. Расхождение шанса крита
объяснено: бросок берёт два соседних выхода ГСЧ игры, они связаны — реальный шанс считается таблицей
(`roll_table.py`), 3000 ударов `roll_probe.lua` с ней сходятся (`notes.md`, «Real hits»).

### 8. Реакции (2026-10-23)
Реакция юнита (`+0x3A`), условия срабатывания всех 15 реакций (`notes.md`, «Reactions»), в калькуляторе — уворот
(Reflex, Strikeback, Block Arrows: шанс 0) и ответный удар (Counter, Strikeback, Bonecrusher ×1.5) с уроном и шансом,
остальные — текстом. В инспекторе — выбор Support и Reaction из списка расы. Тест `tests/test_ffta_reactions.das`.
Не моделируется: статусы, блокирующие реакции, условие HP у Last-реакций, сами эффекты Return Magic / Return Fire.
